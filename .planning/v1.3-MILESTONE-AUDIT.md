## Critical Cross-Phase Gaps

### B1 — Phase 27/28 blockers cannot be resolved in Phase 34

Phase 32 includes retained-code, residual-risk, readiness, and demotion rows from Phases 27 and 28. Phase 34 derives expected rows only from accepted Phase 31 receipts and matches blockers only by the Phase 31 source reference and gate. Every unmatched Phase 27/28 row becomes a blocked `dangling-blocker`, and its Phase 33 decision references are discarded.

The current generated artifacts show 43 Phase 32 blockers: 10 retained-code, 29 readiness, and 4 intake rejections. Phase 34 turns all 43 into dangling blockers and adds four required-row-missing entries. Supplying all four intake streams removes the intake failures, but 39 Phase 27/28 rows still cannot clear.

Source evidence: `tools/bazel/phase32_blocker_register_triage.py:592-761,875-882` and `tools/bazel/phase34_final_readiness_demotion_dry_run.py:748-845`.

### B2 — Release-signing row tables are classified as unknown

Phase 31 validates each Phase 26 release row but stores the row-table reference in its receipt. Phase 32 loads that table object as though it were a single row and checks for a top-level `status`. The table has `rows`, not a top-level status, so a valid all-passed release packet becomes a critical `unknown_unclassified` blocker.

Source evidence: `tools/bazel/phase31_final_evidence_intake.py:750-806` and `tools/bazel/phase32_blocker_register_triage.py:473-480,544-571`.

### B3 — Upstream Phase 34 failure can preserve stale authority

Phase 34 publishes a blocked replacement when demotion-handoff loading fails, but earlier failures while loading Phase 31, Phase 33, normalized decisions, register digests, or the blocker register occur before output replacement. Because `rust_workflow.sh` uses `set -euo pipefail` and runs Phase 34 before Phase 35, such a failure prevents Phase 35's atomic blocked fallback from running.

Direct Phase 35 failure replacement remains correct. The broken boundary is the full workflow when an upstream Phase 34 source fails.

Source evidence: `tools/bazel/phase34_final_readiness_demotion_dry_run.py:1312-1345` and `tools/bazel/rust_workflow.sh:222-232`.
