## Integration Findings

### Aggregate CI stops at Phase 13

`.github/workflows/ci-evidence.yml` runs:

```text
python3 tools/bazel/phase13_ci_evidence.py --ci --output-dir build/ci-evidence/phase13
```

`phase13_ci_evidence.py` then runs only the Phase 13 contract/workflow checks and
`tools/bazel/phase11_verify.py --quick`. It does not run Phase 14, 15, 16, 17,
or 18 verifiers, and the workflow uploads only `build/ci-evidence/phase13/`.

This blocks the milestone-level interpretation of CIEV-01, CIEV-02, and CIEV-03.

### Release-candidate artifact identity is empty

`tools/bazel/BUILD.bazel` defines:

```python
filegroup(
    name = "phase17_release_candidate_artifacts",
    # Wire only real release-candidate outputs here; keep local smoke fixtures separate.
    srcs = [],
)
```

This is an honest no-overclaim boundary, but it means the release-candidate build
flow is not producing actual RC artifacts yet. The Phase 17 smoke target is not a
substitute for release output.

This blocks milestone-level REL-01 and contributes to REL-02/REL-03 and
REV-02/REV-03 gaps.

### Final review consumes contracts, not upstream results

Phase 18 source-ref validation maps to prior phase contracts and manifests, not
to actual generated result manifests for Phase 14-17 evidence runs. The decision
input path accepts guarded `external://phase18/...` evidence refs after schema and
redaction validation, but does not independently prove the upstream result
manifests passed.

This preserves the no-local-approval boundary, but it is not enough for a clean
milestone archive because final readiness can be shaped by decision metadata
without machine-checking the upstream gate outcomes.
