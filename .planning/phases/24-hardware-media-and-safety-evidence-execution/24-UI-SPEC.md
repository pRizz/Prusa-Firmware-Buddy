# Phase 24 - UI Design Contract

> Visual and interaction contract for evidence packet and operator review surfaces. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none |
| Icon library | none |
| Font | System sans for prose and labels; system monospace for scenario IDs, JSON keys, artifact refs, requirement IDs, and hashes |

Source: repo scan found no `components.json`, Tailwind config, React/Next/Vite app config, or existing TSX component library. This phase is not a frontend redesign. The contract applies only if Phase 24 exposes or documents operator evidence packet surfaces, review summaries, tables, forms, templates, CLI summaries, or generated Markdown/HTML review artifacts.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Status chip inner gaps, icon/text gaps if icons are ever added |
| sm | 8px | Table cell horizontal padding, compact form field spacing |
| md | 16px | Default block spacing between summary, filters, table, and validation panels |
| lg | 24px | Page or document section padding |
| xl | 32px | Major breaks between packet metadata, scenario table, and validation summary |
| 2xl | 48px | Top-level evidence packet sections only |
| 3xl | 64px | Not used in Phase 24 evidence review surfaces unless a printable packet requires page-level separation |

Exceptions: Interactive controls, if implemented, must have a minimum 44px hit target. Dense read-only table rows may be 32px high when all row text remains readable and line-wrapped cells do not overlap.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 | 1.5 |
| Label | 12px | 600 | 1.3 |
| Heading | 18px | 600 | 1.2 |
| Display | 24px | 600 | 1.2 |

Use exactly these four sizes and two weights for any rendered review surface. Do not scale type by viewport. Use monospace at the same role size for IDs and refs; do not shrink evidence refs below 12px.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | #FFFFFF | Main review background, printable packet background |
| Secondary (30%) | #F6F8FA | Table header rows, metadata panels, validation summary panels |
| Accent (10%) | #0969DA | Artifact-ref links, active table filters, focused form controls, copy-ref controls |
| Destructive | #D1242F | Failed rows, rejected validation rows, destructive actions only |

Accent reserved for: artifact-ref links, active filters, focused inputs, copy-ref controls, and selected table rows. Do not use accent for every status or every interactive element.

Status labels must never rely on color alone. Each status chip must show the exact text value: `passed`, `failed`, `blocked`, or `exception-requested`.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Submit Evidence Packet |
| Empty state heading | No hardware evidence packet supplied |
| Empty state body | Supply a sanitized Phase 24 packet or run quick mode to generate a blocked placeholder. Real hardware proof requires one row for every Phase 15 scenario. |
| Error state | Evidence packet rejected: {specific reason}. Correct the named scenario row, artifact ref, metadata field, or redaction issue and rerun Phase 24 verification. |
| Destructive confirmation | None: destructive actions are out of scope for Phase 24. Do not add delete, reset, or purge controls to the evidence review surface. |

All copy must be direct, auditable, and operator-facing. Do not use marketing copy, decorative helper text, or wording that implies release readiness, maintainer acceptance, final readiness, or reference demotion.

## Evidence Surface Scope

Phase 24 UI means evidence review UX, not printer firmware UI redesign. The only in-scope surfaces are:

Primary focal point: the packet validation summary/status counts, followed by the full scenario review table.

| Surface | Contract |
|---------|----------|
| Operator input template | Machine-readable form or JSON template for sanitized hardware/media/safety evidence. |
| Packet validation summary | Dense summary of pass/fail/block/exception counts and rejection reasons. |
| Scenario review table | One visible row per Phase 15 scenario, preserving the 26 canonical scenario IDs and source order. |
| Artifact/ref review | Bounded artifact refs, redaction state, source-ref state, and residual-risk text. |
| Upstream row preview | Single downstream-consumable evidence row for later acceptance phases. |

Out of scope: new web app framework, decorative dashboard, printer GUI redesign, live-service evidence, release/signing evidence, retained-code decisions, final readiness approval, and reference demotion approval.

## Operator Evidence Form Contract

Packet-level fields must be visible or documented together before scenario rows:

| Field | Required | Display Contract |
|-------|----------|------------------|
| `evidence_run_id` | yes | Monospace, copyable if interactive. |
| `phase_lifecycle_id` | yes | Must match Phase 24 lifecycle context. |
| `firmware_identity` | yes | Show build identifier without exposing firmware payload bytes. |
| `operator` | yes | Show responsible operator or maintainer identifier. |
| `started_at` / `completed_at` | yes | Use ISO-like timestamp text; no relative-only dates. |
| `source_contract_ref` | yes | Must point to the Phase 15 hardware evidence contract. |

Scenario row fields must be represented in the template and review table:

| Field | Required | Display Contract |
|-------|----------|------------------|
| `scenario_id` | yes | Monospace; must be one of the 26 Phase 15 IDs. |
| `status` | yes | Exact Phase 24 value: `passed`, `failed`, `blocked`, or `exception-requested`. |
| `source_status` | yes | Preserve Phase 15 context; pending/manual/unavailable statuses cannot be shown as a Phase 24 pass. |
| `status_reason` | yes | One concise operator-readable sentence. |
| `artifact_refs` | yes | One or more safe refs under `build/ci-evidence/phase24/...` or `external://phase24/...`. |
| `redaction_status` | yes | Must be `passed` for any passed row. |
| `source_ref_status` | yes | Must be `passed` for any passed row. |
| `device`, `printer_family`, `board` | yes | Keep separate columns; do not merge into a generic device label. |
| `firmware_build`, `operator`, `timestamp` | yes | Required evidence identity fields. |
| `media_surface` | conditional | Required and visible for storage/media rows. |
| `auxiliary_surface` | conditional | Required and visible for auxiliary/MMU/RS485/toolchanger rows. |
| `residual_risk` | yes | Required even for passed rows; empty means blocked or rejected. |
| `failure_observations` | conditional | Required for failed, blocked, storage/media, and safety rows. |
| `exception_request` | conditional | Required only for `exception-requested`; show owner, rationale, evidence ref, and revisit condition. |

## Evidence Review Table Contract

Use a dense table, not cards. The default table must show all 26 Phase 15 scenarios in source-contract order.

| Column | Width Behavior | Required Content |
|--------|----------------|------------------|
| Status | Fixed compact | Exact status text chip. |
| Scenario ID | Fixed/monospace | Canonical Phase 15 ID. |
| Title | Flexible | Scenario title from source contract. |
| Scope | Compact | `hardware-observation` or `source-contract`. |
| Printer / Board | Compact | Printer family and board, not collapsed. |
| Media | Compact | Media surface, or `none`. |
| Auxiliary | Compact | Auxiliary surface, or `none`. |
| Artifact Refs | Flexible/monospace | Safe refs only; wrap at path separators. |
| Residual Risk | Flexible | Required text; never hidden for passed rows. |
| Blocker / Error | Flexible | Validation or operator reason when not passed. |
| Requirements | Compact/monospace | Requirement IDs, including `EVID-02` and source requirement refs when present. |

If filters are implemented, provide only these filters: status, printer family, board, media surface, auxiliary surface, requirement ID, and text search over scenario ID/title. Default view is unfiltered and sorted by Phase 15 contract order. A filter must never hide status counts or missing coverage warnings.

## Status Vocabulary

| Status | Meaning | Review Treatment |
|--------|---------|------------------|
| `passed` | Real sanitized evidence was supplied, refs are bounded, redaction/source refs passed, and residual risk is recorded. | Counts as covered for Phase 24 only. Does not imply live-service proof, release readiness, maintainer acceptance, final readiness, or reference demotion. |
| `failed` | Scenario was executed or validated and did not satisfy the evidence contract. | Show failure reason and artifact refs. Aggregate remains failed unless corrected or later exception-approved outside Phase 24. |
| `blocked` | Required scenario is missing, unavailable, incomplete, redaction-tainted, source-ref invalid, or still Phase 15 pending/manual/unavailable. | Show blocker reason. Aggregate remains blocked. |
| `exception-requested` | Maintainer requests an exception with owner, rationale, evidence ref, and revisit condition. | Show exception metadata. Must not render as pass. |

Forbidden pass normalization: `pending-hardware-input`, `manual-hardware-required`, and `blocked-hardware-unavailable` must render as `blocked` unless the row explicitly renders as `exception-requested` with complete exception metadata.

## Validation Message Contract

| Condition | Required Message Pattern |
|-----------|--------------------------|
| Missing scenario | `Evidence packet rejected: missing scenario result {scenario_id}. Add one row for every Phase 15 scenario.` |
| Duplicate scenario | `Evidence packet rejected: duplicate scenario result {scenario_id}. Keep exactly one row per Phase 15 scenario.` |
| Unknown scenario | `Evidence packet rejected: {scenario_id} does not resolve to the Phase 15 hardware evidence contract.` |
| Invalid status | `Evidence packet rejected: {status} is not a Phase 24 status. Use passed, failed, blocked, or exception-requested.` |
| Pending source passed | `Evidence packet rejected: {scenario_id} cannot pass with source_status {source_status}. Provide real evidence or keep the row blocked.` |
| Missing exception metadata | `Exception request rejected: {scenario_id} requires owner, rationale, evidence_ref, and revisit_condition.` |
| Unsafe artifact ref | `Evidence packet rejected: {artifact_ref} must stay under build/ci-evidence/phase24/ or external://phase24/.` |
| Secret-bearing content | `Evidence packet rejected: secret-bearing or raw payload content detected. Replace raw data with sanitized artifact references.` |
| Storage media collapsed | `Evidence packet rejected: storage evidence must name the specific media surface, observed behavior, failure observations, and residual risk.` |
| Safety coverage unresolved | `Evidence packet blocked: safety evidence is incomplete for {scenario_id}. Provide watchdog, thermal, motion, safe-output, UI-input, MMU, RS485, toolchanger, or auxiliary-controller evidence as required.` |
| Overclaim wording | `Evidence packet rejected: Phase 24 hardware evidence cannot claim release readiness, maintainer acceptance, final readiness, or reference demotion.` |

Messages must identify the specific row or field whenever possible. Do not emit generic `validation failed` copy without a row, field, or next action.

## Artifact And Reference Semantics

| Ref Type | Contract |
|----------|----------|
| Local generated evidence | Must be repo-relative under `build/ci-evidence/phase24/`. |
| External retained evidence | Must use `external://phase24/...` and must not contain path traversal or trailing slash placeholders. |
| Source contract | Must reference `tools/bazel/manifests/phase15_hardware_evidence_contract.json`. |
| Upstream row | Must identify `criterion_id=final-hardware-safety-media-evidence`, `evidence_family=hardware`, `requirement_ids=["EVID-02"]`, phase, lifecycle ID, manifest ref, artifact refs, redaction status, source-ref status, and whether real hardware evidence was supplied. |

Never display or retain private keys, certificates, tokens, Wi-Fi credentials, raw crash dumps, raw RAM dumps, firmware payload bytes, BBF payloads, DFU payloads, or raw service payloads.
