# Phase 5 Unsafe and Runtime-Boundary Audit

This audit seeds the runtime-boundary surfaces that later Phase 5 plans must implement as narrow Rust facades. It is intentionally evidence-classed: local checks can prove manifest completeness and API shape, but hardware-timed behavior remains non-local until simulator or board evidence exists.

## Local vs Non-Local Evidence

`local manifest/static/Rust checks` prove only schema completeness, source-path coverage, source-audit traceability, and Rust API shape. They do not prove MCU clock, interrupt, DMA, watchdog, mutex timing, semaphore wakeup timing, event-group ordering, or scheduler timing behavior.

Those runtime behaviors require `simulator-flow`, `hardware-smoke`, or `manual-hardware-required` evidence in later Phase 5 plans before a replacement can claim parity.

## Synchronization Source Coverage

The FreeRTOS synchronization rows intentionally name `src/freertos/mutex.cpp`, `src/freertos/binary_semaphore.cpp`, `src/freertos/counting_semaphore.cpp`, `src/freertos/wait_condition.cpp`, `include/tasks.hpp`, and `src/common/tasks.cpp` because TaskDeps readiness and synchronization timing are coupled.
