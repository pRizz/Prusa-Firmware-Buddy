<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Bazel action inputs to artifact packager | Fixture payloads, product metadata, and resource seeds cross from declared Bazel inputs into output-producing helper scripts. |
| Artifact outputs to normalized manifests | Manifest truth must come from produced files and validated metadata, not unchecked string claims. |
| Local fixture evidence to release parity claims | Deterministic local fixtures must not be confused with runtime, signing, simulator, hardware, or byte-parity evidence. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Information Disclosure | `tools/bazel/fixtures/`, `tools/bazel/manifests/` | mitigate | Use deterministic non-secret fixture contents, `unsigned-local` signing mode, and verifier scans for private-key PEM markers and `SIGNING_KEY=`. |
| T-03-03 | Spoofing/Tampering | `tools/bazel/artifact_rules.bzl`, `tools/bazel/artifact_packager.py`, `tools/bazel/artifact_manifest.py` | mitigate | Build artifacts through declared Bazel actions, validate product metadata, reject path traversal in helpers, and derive manifest hashes from produced files. |
| T-03-04 | Denial of Service / Information Disclosure | `tools/bazel:representative_release_artifacts`, `tools/bazel:artifact_manifest_smoke` | mitigate | Keep local artifact labels on deterministic package-surface fixtures and do not invoke full firmware builds, private signing keys, simulator flows, or guarded reference commands. |
</threat_model>
